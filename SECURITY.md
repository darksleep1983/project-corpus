# Security policy

[Русская версия](SECURITY.ru.md)

Do not open a public issue for a vulnerability that could permit path escape, unauthorized writes, backup bypass, receipt bypass, secret disclosure, or remote-code execution.

For a private review build, contact the repository owner directly through the private channel listed on their GitHub profile. Before public release, configure GitHub Private Vulnerability Reporting.

Never include real tokens, cookies, credentials, private Corpus files, audit logs, or machine-specific secret paths in a report.
