# Политика безопасности

Не создавайте публичную Issue для уязвимости, которая может позволить выход за
разрешённый путь, неавторизованную запись, обход backup или receipt, раскрытие
секрета либо удалённое выполнение кода.

Пока проект находится в private preview, свяжитесь с владельцем репозитория через
закрытый канал, указанный в его GitHub-профиле. Перед публичным релизом включите
GitHub Private Vulnerability Reporting.

Никогда не прикладывайте реальные токены, cookies, credentials, приватные файлы
Corpus, audit logs или machine-specific secret paths.
