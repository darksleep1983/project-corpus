# Использование своего MCP

[English](own-mcp.md)

Project Corpus не поставляет MCP-сервер. Используйте `OWNER_MCP` только после
выбора и проверки сервера или файлового connector, которому вы доверяете.

## Минимальные требования

Ограничьте сервер одним точным корнем Corpus. Предпочтителен сервер, который
умеет:

- показывать список файлов и полностью их читать;
- возвращать metadata или SHA-256;
- ограничивать запись известными current-файлами и прямыми дочерними файлами
  `Tasks/` или `Report/`;
- блокировать path traversal и устаревшие записи;
- сохранять старое содержимое в backup;
- проверять запись через readback;
- возвращать audit receipt.

Это рекомендации, а не возможности данного репозитория. Записывайте только то,
что реально проверили.

## Подключение

1. Следуйте документации по установке и безопасности выбранного сервера.
2. Ограничьте его filesystem root выбранной папкой Corpus.
3. Выполните официальную настройку MCP для своего AI-клиента.
4. Запишите имя сервера, transport, точный root, tools, аутентификацию, поведение
   записи и backups, а также время проверки в `CORPUS_ACCESS_CURRENT.md`.
5. В новой сессии проверьте соединение настоящими tools сервера.

Универсальной команды `corpus_health` нет. У сервера может быть другая проверка
health или не быть её вовсе.

## Безопасная первая проверка

Убедитесь, что соединение показывает root Corpus и полностью читает `AGENTS.md`.
Проверьте, что несвязанные пути не входят в разрешённый scope. Запись тестируйте
только на одноразовом Corpus или в явно разрешённом scoped Task.

Не открывайте локальный неаутентифицированный сервер в публичный интернет только
ради подключения облачного клиента.

Документация протокола: <https://modelcontextprotocol.io/docs/>
