# Как это работает — без технической каши

[English](how-it-works.md)

Project Corpus отделяет память проекта от конкретного чата или AI-клиента.

## Семь current-файлов

- `AGENTS.md` хранит рабочие правила.
- `OPERATOR_PROFILE.md` задаёт стандарт качества.
- `PROJECT_ROADMAP_CURRENT.md` описывает проект и следующий шаг.
- `CORPUS_ACCESS_CURRENT.md` фиксирует способ получения и синхронизации файлов.
- `LOADER_PROMPT_CURRENT.md` содержит короткую последовательность запуска.
- два handoff-файла сохраняют краткий и подробный контекст.

`Tasks/` содержит точные рабочие задания. `Report/` фиксирует, что действительно
выполнено и проверено.

## Три двери к одному Corpus

```text
локальные файловые tools ─┐
свой MCP ─────────────────┼→ одни и те же семь current-файлов
ручная загрузка ──────────┘
```

Способ доступа меняется, но порядок полномочий и роли файлов остаются прежними.

## В новой сессии

```text
определить режим доступа
→ получить семь current-файлов
→ сначала прочитать AGENTS.md
→ прочитать остальные current-файлы
→ загрузить только нужные Tasks и Reports
→ выдать квитанцию загрузки
→ продолжить с точного следующего шага
```

## При синхронизации

Вперёд переносятся только фактические изменения. `AGENTS.md` и
`OPERATOR_PROFILE.md` защищены в обычной работе. В режиме прямой папки или MCP
tools могут записывать файлы после разрешения; в ручном режиме AI возвращает
замены, а владелец сам их сохраняет.

Памятью являются файлы. MCP — только один необязательный путь к ним.
