# Candidate good first issues

These are small, useful contributions for the owner to turn into Issues after
reviewing scope and priority. They are deliberately not pre-created Issues.

1. Add a fourth V2 example for a planning-only project, including a conforming
   template tree and a short explanation of what is deliberately unverified.
2. Add an invalid V2 conformance fixture for an `ACTIVE` status with no exact
   next action, including its expected diagnostic.
3. Improve the CLI's `--help` examples with a no-mutation diagnostic walkthrough.
4. Add a concise Russian translation plan for the English-first documentation
   site, preserving links to the existing bilingual repository documents.
5. Document how a maintainer records local filesystem evidence after a runner
   image or Python matrix change.
6. Add a focused documentation example explaining policy drift and why it
   leaves controlled mutation suspended.
7. Review the V1-to-V2 migration guide for a newcomer-facing terminology
   clarification without changing its create-only migration contract.
8. Add accessibility-oriented alt text review for repository and site visual
   assets, including dark/light background readability.

Do not label a task “good first issue” if it needs an architecture decision,
security guarantee expansion, external service account, or a release decision.
