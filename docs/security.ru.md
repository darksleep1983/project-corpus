# Модель безопасности

Project Corpus намеренно имеет узкие полномочия.

- Один экземпляр сервера настраивается на один корень Corpus.
- Сервер разрешает и проверяет каждый путь внутри этого корня.
- Записи в корне ограничены известными current-файлами.
- Новые файлы можно создавать только прямо в Tasks/ или Report/ и только в Markdown.
- OPERATOR_PROFILE.md недоступен для записи.
- AGENTS.md требует прямой авторизации изменения протокола.
- Обновления требуют точный текущий SHA-256.
- Backups и audit receipts находятся вне Corpus.
- Streamable HTTP по умолчанию должен быть привязан только к loopback; SDK также
  отклоняет запросы с недоверенным Origin.

## От чего это не защищает

- от человека, который уже контролирует вашу учётную запись ОС;
- от второго независимого писателя, меняющего файлы в обход сервера;
- от HTTP endpoint, открытого в недоверенную сеть;
- от секретов, которые намеренно положили в Markdown;
- от небезопасных инструкций, которые принял AI-клиент.

Запускайте сервер на loopback, проверяйте код, используйте одного авторитетного
писателя на Corpus и храните секреты в другом месте.
